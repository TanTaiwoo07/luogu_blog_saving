## 基础概念 Q1-Q4

### Q1. 排序稳定性是什么？有什么实际用途？

相等元素排序后保持输入相对次序，即为稳定。

用途是**多关键字排序**：先按次要关键字排（或不排），再用稳定排序按主要关键字排，次要关键字的次序自动保留。典型场景是按分数排序但同分者保持录入顺序，或表格点列头做多级排序。

稳定五家：冒、插、归、计、基。不稳四家：选、希、快、堆。
详见 [详解 §0](cpp-sorting-algorithms.md#0-预备知识与评价指标)。

### Q2. 快排、归并、堆排怎么选？

| 维度 | 快排 | 归并 | 堆排 |
| :--- | :--- | :--- | :--- |
| 平均速度 | 最快（常数最小） | 次之 | 最慢 |
| 最坏情况 | O(n²) | O(n log n) | O(n log n) |
| 额外空间 | O(log n) 栈 | O(n) | O(1) |
| 稳定性 | 否 | 是 | 否 |
| 缓存友好 | 是（顺序扫描） | 是 | 否（跨层跳跃） |

默认选快排（即 `std::sort`）；要稳定性或外部排序选归并；内存极紧且要最坏保证选堆排。

### Q3. 哪些排序是原地的？哪些有最坏 O(n log n) 保证？

原地 O(1)：冒泡、选择、插入、希尔、堆排。
最坏 O(n log n)：归并、堆排、`std::sort`（Introsort）。

两者交集只有**堆排序**——既原地又有最坏保证，这是它存在的理由。

### Q4. 插入排序什么时候比快排快？

两种情况：一是 n 很小（≤ 50），插入排序的常数因子远小于快排的递归与函数调用开销；二是数据近乎有序，逆序对少时插入排序接近 O(n)。

这也是所有工业级排序（含 `std::sort`）在小区间切换到插入排序的原因。

## 复杂度与证明 Q5-Q9

### Q5. 快排什么时候退化到 O(n²)？怎么避免？

每次划分极度失衡时退化：pivot 总是取到当前区间的最大或最小值，递归树退化成链。典型触发是**已排序数组 + 取首/尾元素作 pivot**；全相等元素在二路划分下同样退化。

避免手段：三数取中或随机化 pivot；小区间切换插入排序；用三路划分处理大量重复元素；加递归深度限制，超限转堆排序（Introsort，即 `std::sort` 的做法）。

详见 [详解 §6.6](cpp-sorting-algorithms.md#66-常见优化点)。

### Q6. 比较排序下界为什么是 Ω(n log n)？非比较排序为何能突破？

决策树模型：任何基于比较的排序都可表示为一棵二叉决策树，每次比较对应一个内部节点、一种输入排列对应一片叶子。n 个元素有 n! 种排列，故叶子数 ≥ n!，树高（即最坏比较次数）≥ log₂(n!) = Ω(n log n)（由 Stirling 公式）。平均情况同理。

非比较排序（计数、桶、基数）不作"两元素比较"，决策树前提不成立，它们通过值域索引直接定位，代价转移到值域 k 或位数 d 上，因此可达线性。

### Q7. 建堆为什么是 O(n) 而不是 O(n log n)？

逐个插入建堆确实是 O(n log n)。但 Floyd 自底向上建堆中，**下沉代价与节点高度成正比，而节点数随高度指数递减**：第 h 层（从底数）至多 n / 2^(h+1) 个节点，每个下沉至多 h 层，总代价 Σ h · n / 2^(h+1) < 2n = O(n)。

关键是"绝大多数节点在底层，下沉距离极短"。

### Q8. 堆排序理论 O(n log n)，为什么实践中慢于快排？

两个原因：

1. **缓存局部性差**。堆是数组表示的树，下沉路径沿 `2i+1` / `2i+2` 跳跃，跨越 log n 层，每层大概率 cache miss；快排的划分是连续顺序扫描，几乎全部命中缓存。
2. **分支预测失败率高**。下沉循环中的"走左还是走右"依赖数据，不可预测；快排的划分循环虽有分支，模式更规整。

另外堆排序的比较次数本身也多于快排。

### Q9. 希尔排序的复杂度到底是多少？

**没有确定值**，取决于 gap 序列的选择，这是它最大的理论缺陷：

| gap 序列 | 最坏复杂度 |
| :--- | :--- |
| Shell 原始（n/2 折半） | Θ(n²) |
| Hibbard（2^k − 1） | O(n^1.5) |
| Sedgewick | 约 O(n^(4/3)) |

实践上中等规模（数千至数万）表现很好，因为常数小、无递归、缓存友好；但无法给出严格保证，工程中通常改用快排或归并。

## 工程实现 Q10-Q14

### Q10. std::sort 为什么不用纯快排？

纯快排有 O(n²) 最坏风险。`std::sort` 用 **Introsort（内省排序）**：主体是快排，监控递归深度，超过 `2 · ⌊log₂ n⌋` 判定划分退化，切换为堆排序兜底；所有长度 ≤ 16 的子区间用插入排序收尾。

这个三段式同时取得快排的平均性能、堆排的最坏保证、插排的小区间常数优势。C++11 起标准明确要求 O(n log n) 次比较（C++03 只要求平均）。

详见 [详解 §11](cpp-sorting-algorithms.md#11-stdsort-的实现思路与使用要点)。

### Q11. std::sort 崩溃最常见的原因是什么？

比较器不满足**严格弱序**。三条必须同时成立：

1. 非自反：`comp(a, a) == false`；
2. 非对称：不能同时有 `comp(a, b)` 与 `comp(b, a)`；
3. 可传递（以及等价关系可传递）。

写成 `return x.key <= y.key;` 是最常见的错误，会导致划分指针越过边界、越界访问。

其他坑：比较器有副作用；用 `std::sort` 排序 `std::list`（需随机访问迭代器，链表要用成员函数 `sort()`）。

### Q12. 如何用 O(1) 额外空间实现稳定排序？

思路是**用时间换空间**：

- 选择排序的稳定化改造：把"与最小元素交换"改为"区间整体右移一位"，移动次数升到 O(n²)，但空间 O(1) 且稳定。
- 原地归并：理论上存在 O(1) 空间的稳定归并算法，但常数极大，工程上不用。

若允许 O(n) 空间，`stable_sort` 是正解。不允许时先看能否用"排序索引数组"绕开——排序索引只需 O(n) 的 int，比移动大对象便宜得多。

### Q13. 计数排序值域太大怎么办？

k >> n 时 O(n + k) 的空间与初始化代价不可接受，三条出路：

1. **分块**：按值域切成若干段，段内计数，本质是退化成桶排序；
2. **换算法**：改用比较排序（O(n log n) 与 k 无关）；
3. **离散化**：只需相对次序时，先离散化到 0 ~ n-1 再计数。

### Q14. 基数排序能排负数和字符串吗？

**负数**：可以，但要处理。常用做法是分离负数与非负数——负数取绝对值后按基数排序，再逆序拼接到结果前面；或整体加一个偏移量转成非负。

**字符串**：可以，但要用 MSD（高位优先）处理变长串——短串排在长串前缀位置时直接结束；LSD 要求各位等长，只适合定长字符串。变长字符串大规模排序另有 burstsort 等专门算法。

## 场景题 Q15-Q19

### Q15. 一亿个数取前 100 大，怎么做？

**不要全排序**（O(n log n)）。用大小为 100 的**小顶堆**扫描一遍：堆未满就压入，满了则只在元素大于堆顶时替换堆顶。

复杂度 O(n log K) = O(n log 100)，内存 O(K)，且**支持流式输入**（数据不必全部驻留内存）。

若数据已在内存中且只要"第 100 大那个值"，`nth_element` 平均 O(n) 更快，但它需要随机访问全部数据。

### Q16. 10GB 数据、只有 1GB 内存，怎么排序？

**外部归并排序**：

1. 按可用内存切分，每次读入一个块（如 800MB），内部排序后写回磁盘成一个有序段（run）；
2. 对多个 run 做 k 路归并，用败者树 / 优先队列选最小，缓冲区轮换，顺序 I/O；
3. 归并趟数为 O(log(N/M))，I/O 复杂度 O(N log(N/M))。

关键点是**顺序 I/O + 多路归并 + 缓冲区管理**，这也是归并排序在数据库与外部排序中不可替代的原因。快排因随机访问模式在磁盘上不可行。

### Q17. 如何在 O(n) 时间找第 K 大？

**快速选择（QuickSelect）**：用快排的划分把区间分成两段，只递归包含目标下标的那一段。期望复杂度 O(n)（T(n) = T(n/2) + O(n)），最坏 O(n²)。

要最坏 O(n) 需用 BFPRT（中位数的中位数）选 pivot，但常数很大，实践中不用。

标准库对应物是 `nth_element`，它采用 introselect（深度限制兜底），平均 O(n) 且无退化风险。

### Q18. 链表怎么排序？为什么不能用 std::sort？

`std::sort` 要求**随机访问迭代器**（需 `it + n`、随机跳转），链表只有双向迭代器，编译不过。

用成员函数 `list::sort()`，它是**归并排序**实现，稳定，O(n log n)，只需改指针、不需要额外数组，也不需要随机访问——这恰好是归并排序相对快排的优势场景。（`forward_list::sort()` 同理。）

### Q19. 桶排序什么时候退化？

输入分布严重倾斜时：所有元素落进同一个桶，复杂度退化为桶内算法的复杂度——桶内若用插入排序就是 O(n²)，而且白白多了分桶开销。

因此实际使用前要么**已知分布均匀**（如 [0,1) 归一化指标），要么先采样估计分布；分布未知且可能倾斜时，直接用比较排序更稳妥。

## 手撕代码 Q20-Q22

### Q20. 面试手撕排序，怎么保证一次写对？

遵循三条：

1. **区间统一用 `[l, r)` 左闭右开**，递归边界写 `[l, m)` 与 `[m, r)`，避免闭区间的 ±1 纠缠；
2. **先写终止条件** `if (r - l <= 1) return;`，再写主体；
3. 写完立刻过 6 个用例：空、单元素、`[2,1]`、`[1,2,3]`（已有序）、`[3,2,1]`（逆序）、`[5,5,5,5]`（全等）。

全等输入是快排死循环的高发区，必测。

模板见 [`sorting-cheatsheet.md` §4](sorting-cheatsheet.md#4-默写模板)。

### Q21. 快排的两种划分写法有什么区别？

| | Lomuto | Hoare |
| :--- | :--- | :--- |
| 指针 | 单指针 + 扫描指针 | 左右双向指针 |
| pivot | 通常换到末尾 | 取中位值（存值不存下标） |
| 返回 | pivot 最终位置明确 | 返回分割点，pivot 不必在位 |
| 全等元素 | 退化 O(n²) | 均衡划分 |
| 代码量 | 稍长，边界清晰 | 更短，但四个坑 |

标准库用 Hoare 风格（`__unguarded_partition`）。面试推荐先写 Lomuto（边界最清晰、最不容易错），能说清 Hoare 的四个坑是加分项。

### Q22. 三个数排序最少需要几次比较？

最少 **3 次**比较（最坏情况）。决策树下界：3! = 6 种排列，⌈log₂ 6⌉ = 3。

用 2 次比较最多区分 4 种情况，不足以覆盖 6 种排列，故 3 次是最优。这个例子是"比较排序下界"最直观的展示，也引出**排序网络**这一方向：它用固定的比较序列（无数据依赖分支）排序，适合 SIMD / 硬件实现。

## 快速背诵清单

```
稳定：冒 插 归 计 基        不稳：选 希 快 堆
O(n²)：冒泡 选择 插入        O(n log n)：归并 快排 堆排
线性：计数 桶 基数（非比较）
最坏 O(n log n)：归并 堆排 std::sort
原地 O(1)：冒泡 选择 插入 希尔 堆排

std::sort = 快排 + 深度超限转堆排 + 小区间插排（Introsort）
快排退化：pivot 总取到极值 → 三数取中 / 随机 / 三路划分 / 深度限制
建堆 O(n)：底层节点多、下沉距离短，Σ h·n/2^(h+1) < 2n
下界：n! 种排列，决策树高 ≥ log₂(n!) = Ω(n log n)
Top-K：小顶堆 O(n log K)，流式可用；nth_element 平均 O(n) 但要全量内存
外存：外部归并，顺序 I/O，k 路归并 + 败者树
```
